## 2026-09-20 本轮纠正

- 保存成功留在存档页并更新卡片，可继续新建、覆盖；关闭窗口才恢复对白。
- 新建按钮一按即保存。原先只选择不提交；透明对白点击层还会挡住卡片。现通过原版 Tips 层打开对话中的整个存档窗口，保留上层原生确认框。
- 原版空槽 DisabledColor 会显示黄框；不再因整个页面 busy 把全部卡片设为 disabled。当前选中槽沿用原版选中样式，悬停只影响鼠标指向槽。
- 保存和读取均不调用右侧 Toast。成功安静刷新；真实错误留在本页底部，原页面在恢复过程中销毁后失败则显示原生错误框；自动保存失败记录日志与状态。
- 读档不再要求当前状态通过 CanCapture，也不再先保存当前世界作回滚。目标完整性/依赖预检通过后直接 RetireCurrent + CloseAllView，清旧回调与自动推进，避免结算已放弃剧情。只有执行恢复真的失败才清理至标题，不把返回标题当读档条件。
- 对话中原生手动、自动、快速存档三个页签可独立访问。切换时保留对话暂停租约，关闭或实际读入普通存档时释放。
- 本插件精确版本和存档 format/adapter 是兼容契约；自身 DLL 仅 UI/性能重编译不再使旧档因 SHA/MVID 不同拒读。第三方插件仍严格比较二进制，自身记录缺失、重复、版本不符仍拒读。

## 性能

原主线程每次全量配置序列化及哈希约3.7秒，总捕获约3.8秒。现主线程同一时点深复制世界和纯配置，后台用私有 serializer 与只读预检合同计算兼容摘要；不共享活动对象或 DataJson，不按 TTL 缓存配置值。配置类属性构造会访问 DescCtrl，因此类型计划只在配置和原生界面就绪后分帧预热；worker 禁止属性反射 fallback。

最新完整通过运行：窗口就绪约373ms；首次主线程捕获约647ms，后续约212–286ms；首次最大帧约654ms。仍有停顿，不宣称彻底不卡。实际全部游戏配置摘要与旧格式一致验证通过。类型计划预热采用软预算，个别首次表达式/JIT可超出单帧预算。这是上一轮基线。本轮已将读取配置哈希移到后台，并加入完整字段比较后复用摘要及一次标题空闲预计算；当前实测结果见下方本轮记录。

## 2026-09-20 存读限制与损坏风险专项修正

- 本次“所有旧档插件不一致”实因隔离 QA 驱动每次重编译改变 SHA/MVID。仅 QA 程序在严格验证隔离路径、原生身份、重定向存档路径和恰好两个插件后，按其固定版本兼容重编译；生产插件没有增加第三方白名单，旧档字节不修改。
- 保存/读档忙时进入队列；重复请求合并。读档取消未提交的旧世界捕获，但等待已经开始的原子写入完成，避免取消回执掩盖实际提交。
- 独立提交回执不依赖 UI 调度队列存活。pending/完成/列表刷新逐观察者隔离异常，读档队尾在 finally 释放，后台禁止调用 UI。
- 本机跨进程锁把父版本校验与发布串行化；临时文件完整验证后原子发布。取消默认 2 GiB/4000 文件总量配额，旧历史不回收。
- 不再因 TalkCfg 含有后续小游戏入口而拒绝保存当前普通对白。实际小游戏进行中的状态仍需要独立适配。
- 正向 BGM 淡入可保存；已知纯音乐资源恢复失败/超时可降级静音，后台迟到的资源不会重新播出。未知含剧情回调的音频不能丢弃。
- 仓库 67 项测试通过，包括真实双进程争用只提交一份、父版本冲突、半文件、损坏、保留旧档和无默认历史配额。配置精确比较 26 项通过；相同引用、数量、TTL 均不作为一致性证据。
- 完整 controls 回归本轮止于旧脚本的“同页至少多个空槽”前提：历史增加后不成立，并非旧档加载结果。保留失败证据，使用 recovery 专项直接覆盖旧档加载和并发，不以放宽 UI 断言代替通过。
- 仍保留的数据保护：校验和、结构/版本、实际缺失或改变的剧情依赖、父版本冲突、权限/磁盘写入失败。删除这些保护不会补齐恢复能力，反而可能使残缺状态继续写入。
- 尚不支持完整保存的特殊状态包括 CG/漫画页、电话状态、纸条、正在进行的引导以及未适配 continuation。不得声称“全部状态无条件可存读”或“彻底排除存档损坏”。
