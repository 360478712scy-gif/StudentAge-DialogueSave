# Game / Service / Host 复核

审查时间：2026-09-19。审查者是 `src/Game/` 的实现作者，因此 Game 部分属于自审；`DialogueSaveService.cs` 与 `Plugin.cs` 由主 agent 实现，本文件对这两部分属于独立审查。以下结论来自源码和异步调用顺序检查，没有把这些路径称作已完成实机验证。

## 本轮待修问题

### P1：加载事务过早释放暂停

`DialogueSaveService.QuickLoad` 的确认回调先 `pause.Dispose()`，然后才调用异步 `Load`。读取文件期间 `busy` 只挡存读档服务，不能挡原版对白的下一句输入。因此用户确认时的稳定节点可能在读盘期间变成正在执行效果的节点，最终恢复会拒绝或从不同状态回滚。

`Load` 在 `adapter.RestoreAsync` 前调用 `EndMenu()`。适配器首先检查版本/配置/Mod/插件指纹，如果这里拒载，原有存档页并未销毁，但服务已清掉菜单拥有权、快照和暂停。界面仍遮着对白，底下却重新可以推进；自动存档也不再被 `menuOpen` 阻挡。

建议：加载使用由服务持有的独立事务暂停租约，覆盖确认后读盘、预检、恢复与失败回传整个过程。已有菜单的暂停不要在预检成功前解除。若预检失败且菜单仍在，应保持原有菜单暂停；成功关闭旧 UI 或用户退出时再释放。确认框暂停也应纳入服务 Dispose/取消路径，不能只存在闭包局部变量中。

验收：故意慢读盘时连按下一句；缺失 Mod/改变指纹后加载失败，菜单仍打开；确认框取消、外部关闭、插件退出。这些路径都不能漏暂停或永久卡住对白。

### P1：账户切换未使菜单快照失效

`EnsureRepository` 换目录时清空 `records` 并提高 `generation`，但保留 `menuCheckpoint/menuSaving/menuPause`；`Publish` 直接采用快照 `Brief.SteamId`，没有再次核对当前用户。可构造：账户 A 打开保存菜单捕获快照，切到账户 B 后刷新仓库，再在旧菜单保存，于是 A 的快照提交到 B 的存档目录。

建议：仓库/账户切换成功时结束旧菜单、重置自动保存节点标记，保存发布前再次核对快照用户与当前用户/仓库用户相同。后台任务持有原来的仓库实例是正确的，不应把正在写的 A 任务迁移到 B；UI 完成通知也应校验账户。

验收：注入两份隔离账户目录，在菜单打开、列表扫描和后台提交三个阶段切换，确保没有跨账户写入或旧菜单继续可提交。

### P1：删除与列表刷新共享代次导致旧结果覆盖

`Delete` 不检查 `IsListing`，也不提高 generation。若扫描已完成读文件但其主线程回调尚未处理，删除任务可完成并发布新列表，随后旧扫描回调用同一代次把 `records` 覆盖回删除前的状态。Repository 的锁保护磁盘操作，但不保证两条 `ContinueWith` 的投递顺序。

建议：删除与扫描互斥，或给列表结果独立递增版本；开始删除时使此前扫描结果失效并正确重置 `IsListing`。

验收：用可控调度器反序投递“扫描完成”和“删除完成”回调，最终列表必须保留删除结果。

### P1：关闭顺序允许恢复任务在退出时尝试回滚

`DialogueRuntimeHost.Shutdown` 先 `shutdown.Cancel()`，后 `adapter.Dispose()`。`NextFrame` 的取消注册会完成等待 Task；其继续执行可能同步发生。此时适配器尚未设置 disposed，恢复 catch 可以开始 rollback 或 `QuietToTitle`，并按未关闭状态释放输入遮挡，和正在退出的游戏竞争。

建议：先将适配器明确置为终止状态，再取消宿主令牌。可以先 Dispose 适配器或增加不触碰 UI 的 `BeginShutdown` 阶段。所有尚未完成的恢复任务看到终止标记后直接退出，不加载世界、不回标题、不重新启用输入。

验收：在世界已换入、角色资源等待、BGM 资源等待三个时刻关闭宿主，检查没有新的主界面/标题打开、没有二次世界 Load，也没有残留输入蒙层。

### P2：仓库初始化失败后留下半初始化字段

`EnsureRepository` 在设备 ID 目录/文件操作前已经赋值 `repository/repositoryPath`。若读取 device-id 或创建目录失败，下次调用看到同路径仓库就直接返回成功，跳过尚未完成的初始化；`deviceId` 可能为空，之后持续报标识无效而无法随权限恢复自行恢复。

建议：先在局部变量中构造仓库并完成设备 ID 读写，全部成功后一次性提交字段；失败不保留半初始化状态。

验收：第一次设备 ID 读取抛异常，第二次正常，第二次应正确恢复，且首次不应进入可提交状态。

### P2：自动存档达到容量限制时仅写日志

手动与快速保存现在能显示 Repository 的具体容量错误，这是正确修复。自动保存失败分支仍只有 log，用户看不到自动存档已经停止；之后会按间隔持续重试相同错误。

建议：容量/数量上限首次命中时向用户显示一次“自动对话存档暂停”及原因，并保持可见状态；限流提醒而非每次弹窗。释放空间或用户重新启用后再重试。

### P2：快速加载忽略同槽位的高版本存档

发布已检查 UnsupportedVersion 同槽位并拒绝写入。但 `QuickLoad` 仍只看 `FindHeads` 返回的 Ready 头部。若同一快速槽有一个旧版可识别头部和一个高版本头部，自动挑选旧版会让用户误以为载入最新快存。

建议：快读也检查同用户/周目/快速槽的高版本条目，明确提示更新插件或进入列表选择，不能静默挑旧档。

## 已确认的合理隔离

- service 的后台工作仅处理 Repository 与已克隆的 world 字节/Dialogue DTO；没有把活 Unity 对象交给后台序列化。
- Publish/Load/Delete 都捕获当时的仓库实例与 generation，普通过期回调会被抛弃；问题是上述扫描/删除共享代次的具体例外。
- 本插件 service、host 与 GameAdapter 没有调用普通 `Game.QuickSaveGame/QuickLoadGame/LoadGame/ManualSaveGame`，也没有写入 `LatestSaveKey`。
- 独立 HideAndDontSave + DontDestroyOnLoad 宿主与引导插件销毁分离；主宿主 Dispose/UnpatchSelf 只使用本插件 Harmony ID。
- Corrupt 且无 Header 的档案现在在手动对话档列表中显示不可加载的保留条目，不再直接隐去。
- 已知高版本同槽位目前禁止写入；容量限制错误传到手动保存用户提示。

## Game 自审与证据边界

适配器采用显式来源追踪，仅支持主界面上的稳定普通回合事件对白。完整段落和无倒计时选项分别校验；已执行效果标记、实际选项、回合模型、未提交引导状态、随机状态与呈现状态一起保存。恢复没有调用 RefreshTalk 重播，也不调用普通 LoadGame 自动消费事件队列。

已增加世界/对白版本及配置检查、Mod 集合与插件指纹校验、旧代次资源回调抑制、失败回滚、HotkeyView 重建、BGM 恢复与输入遮挡。此列表是实现描述，不是全部机制已在真实游戏验收。

`tests/AdapterContractProbe` 对当前安装游戏 DLL 的 87 项元数据契约检查通过；整包编译通过。主 agent 已反馈独立宿主真实启动成功，并发现启动 UI 未就绪访问问题；该问题已加显式 readiness 检查修复。恢复效果去重、选项一致性、UI 真实尺寸和跨机器 Steam Cloud 仍由独立运行证据验收。

全配置指纹每次捕获/预检即时计算，安全优先但需要测量实际耗时。原版角色动作排序比较器对重复入场动作不是严格全序；哈希已在副本应用原版排序，异常配置仍可能保守拒载，不应把这类拒载改成跳过指纹检查。

## 后续实现复核：关闭与异步保存请求

Game 终止分支已修复：Dispose 先置终止状态并递增代次；恢复和回滚的异常分支分别检查终止状态，关闭时不回滚、不重建标题 UI。输入遮罩 Release 在 finally 销毁遮罩，关闭时不重新启用输入。宿主必须先 Dispose adapter、随后取消 nextFrame。上述 service 问题由主 agent 修复，这份独审不将未复查的修改标成通过。

按用户最新要求新增 CaptureAsync：受理当前普通对白请求后阻挡点击、跳过、下一句和限时选项时钟。播放中的文字保留 Anim 阶段和可见字数，暂停 tween 而不执行 DoTextEnd；恢复/关闭菜单后从该位置继续，结束效果仍由原版自然完成路径执行。已进入 DoTextEnd 下一帧续接的短暂状态在内部等待。支持 Countdown 点击阶段和限时 Option，保存实际选项、默认选项及剩余秒数；不重新抽取选项。auto/快进状态和原生 TimerMgr 剩余等待时间存入快照，菜单最后一个暂停租约释放后才恢复；原自动回调在恢复接管前仍被拦截，避免旧 timer 多推进一句。静态背景效果参数改为保存恢复，不再以非零默认值拒存。

continuation 独立组件已接入：按保存时的主界面/地图/地点/NPC 层级重建，使用有限原生回调注册表和 incoming world 引用预检；RoundState、结束事件队列及 MapData 记录字段同时保存恢复。地图重建不重放引导、照片收集、招呼语音；恢复过程中压制 NPC 自动关闭。

元数据契约更新为 121 项通过，全项目编译通过；这不等于异步场景、限时选择和背景效果已经完成实机验收。特殊 CG、漫画、歌词/读报、小游戏内状态、引导中、第三方回调/音频、未进入原生注册表的回调，以及其他活动窗口仍有明确缺口。CaptureAsync 内部资源等待有 20 秒超时，不能宣称已满足“任何情况均可恢复”。本轮不启动游戏、不安装正式目录；主 agent 报告隔离运行受另一任务占用，本次新增逻辑无实机截图或恢复语义验收证据。

## Service 串行请求修复复核

新版 CaptureRequestedAsync 使用独立请求 token 和主线程串行标记，菜单关闭取消自己的请求，快存请求独立排队；已不共享不可取消的捕获任务。Load/QuickLoad 在捕获或已受理保存完成前不替换世界。Save 在发出 Pending 回调前取得 task/token/菜单代次局部变量。上轮新增的三项请求竞态已在静态复核中消除；磁盘 worker 与输入/暂停的真实时序仍须运行验证。列表、账户、容量相关旧发现已部分修复，本次不将其他未重测路径列为实机通过。
