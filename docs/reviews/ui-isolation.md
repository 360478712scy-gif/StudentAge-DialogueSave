# UI、宿主生命周期与隔离审查

审查日期：2026-09-19。本文记录静态审查及修复复核；撰写时首次引擎运行尚未完成，不能当成实机通过报告。

## 一、UI 作者自审

范围：`src/UI/DialogueUiContracts.cs`、`NativeUiCloner.cs`、`DialogueSavePage.cs`、`DialogueUiController.cs`、`UiLayoutDiagnostics.cs`。本节由 UI 实现者完成，**不是独立交叉审查**；其他 agent 的 UI 交叉审查应单独留证。

当前代码保留原 `SaveView` 数据与标签标识；独立入口位于原标签左侧，进入后使用自有列表和原版模板，不把 `.dsav` 塞进 `SaveFileData`。读取页内部另列手动/自动/快速二级分类；保存页只有手动对话槽，不显示自动/快速二级。读取模式按记录展示，跨周目与同槽分叉不去重丢失。顶部新增入口始终称为“对话存档”，原版手动/自动/快速标签始终显示且名称、尺寸、位置不变。工具栏保存页关闭返回当前对话，点原手动标签也只关闭窗口，避免暴露原版原本禁止的普通保存操作；其他情况下点原标签退出对话页并沿用原逻辑。

自审修复：

- 后台扫描把空槽补成已有槽时，清除旧空槽选择，不能跳过覆盖确认。
- 克隆按钮移除原文件操作监听；只绑定对话仓库操作。
- 使用主线程回调与界面代次，关闭后的异步结果不再改动旧 UI。
- 暂停释放或某项卸载失败不截断其余 UI 清理；只撤销本控制器挂接的方法。
- 年份/季节沿用 `SeasonCfg.colors` 的上下渐变。新增 `SeasonId`，旧档仅在季节名称唯一匹配时兼容，不能猜测编号；复用卡片先重置渐变，避免残留上一张卡的颜色。
- 说话人和台词直接显示在原卡片姓名/备注矩形内，沿用字号与字体；按实际文字宽度截断，原版悬浮说明可查看完整台词。

只读 QA 接口：`DialogueUiController.CaptureLayoutReport()` 返回 JSON，不写文件、不强制重排、不发送输入。应在主线程、界面布局稳定并经过 `WaitForEndOfFrame` 后调用。报告包含屏幕边界、原标签数、卡片尺寸与字体一致性、卡片不重叠和容器边界、季节渐变比对、对话操作标签去重。空列表意味着该界面未被观察，不能算通过。

尚需实机验证：四功能项与原有操作的完整布局、不同分辨率、选项不遮挡、鼠标命中及事件穿透、禁用状态提示、重复打开关闭后无重复对象、暂停与取消恢复。`Button.onClick.Invoke()` 只能验证监听路由，会绕过实际命中测试和 `interactable` 检查，不能作为真实点击验收。

## 二、Plugin.cs 独立审查

此文件由主 agent 实现，本节为独立源码审查。

- 独立 `DontDestroyOnLoad` 宿主承载 UI、适配器和队列，BepInEx 引导对象销毁不立即卸载运行插件；源码方向符合游戏启动生命周期。
- 可用状态每秒比较一次，只有变化才刷新操作栏；点击时仍由服务门禁复核。`ui.Tick()` 处理窗口加载超时。
- 曾发现 P1：串行 `Shutdown` 无异常隔离，取消或暂停释放异常可能阻止后续补丁卸载。当前已复核修复为各阶段独立 `Cleanup`，最终清空队列并清除静态宿主；自有 Harmony 在清理中单独撤回。
- 编译和静态检查不能证明引导对象清理后运行、关闭时实际卸载及与其他插件共存；这些仍需真实日志与操作证据。

## 三、QA 隔离方案独立审查

范围：`tools/prepare_qa.py`、`tools/QaRewrite/Program.cs`、`tests/QaIsolation.cs`，以及补强后的 `tools/rename_qa_player.py`、`tests/RuntimeQA.cs`。本节未修改这些被审代码。

最初阻塞点与当前复核：

1. **原生偏好身份共享。** 仅替换托管 `PlayerPrefs` 调用不足以隔离 Unity 原生 `Screenmanager` 和会话键。同一 bottle 的正式注册表确有这些键。补强脚本现在只修改 QA `data.unity3d` 中 `PlayerSettings` 的等长公司/产品字段，并同步 `app.info` 为 `DlgSaveQA / DialogSave`；运行驱动会核对 `Application.companyName/productName`。该补强解决了原先命名空间共享的设计缺口，仍须运行后检查实际身份及正式偏好未变化。
2. **可重新启动正式安装。** 原 `SteamManager.Awake` 与 `SteamPlatform` 可调用 `SteamAPI.RestartAppIfNecessary`。当前重写器已阻断该入口，防止 QA 因启动条件不符转而启动正式副本。
3. **Steam 写入漏项。** 已补上 Workshop 下载、投票和 RichPresence。游戏成就写入走 `SteamUserStats.SetAchievement/SetStat/StoreStats`，当前都列入阻断。报告不能外推为所有未来 SDK 方法都已覆盖。
4. **仅确认存在两条改写不足。** 当前已增加重写后全程序集扫描，要求无残留 `persistentDataPath` / `PlayerPrefs` 调用，且列入 BLOCK 的方法没有调用指令，数量一致。

已做的只读检查：

- 正式和 QA 资源树当时均无符号链接，正式与 QA 的 `Assembly-CSharp.dll` inode 不同。
- 当前 `PathDefine` 的普通/测试存档、全局档、图片、音乐根目录由 `persistentDataPath` 派生；Mod 启用列表由 `Application.dataPath` 派生。
- `QaPrefs` 为仅内存字典，不写正式注册表；正式副本路径未被审查过程修改。
- 原版程序集的 hash 应在实际启动前固定，并在退出后比较；偏好及正式存档也需对应的前后证据。只在准备末尾生成一次 hash 不能单独证明前后未变化。

隔离结论的范围：这些补强可作为**受控 QA 副本运行的前置门禁**；必须先成功完成重写复扫、QA 原生身份准备和路径核对，测试只写项目 `qa/`。不得把该测试描述成完全控制了 Steam 客户端自身行为。只声明 QA 新档被重定向到项目目录、不会写入原版 AutoCloud 存档目录；不声明 Steam 客户端自身同步已关闭，也不声明跨设备云存档验收通过。

本审查没有运行游戏或写入正式游戏、用户存档、注册表与 Steam 云端。

## 五、自然工具栏与暂停菜单修正（2026-09-20，验收进行中）

初次工具栏缺失的确定源码缺陷：RefreshActions 只枚举已经成功装饰的字典；首次刷新因对白/顶部窗口未就绪而提前返回后，不会再次发现原生 HotkeyView。已改为直接发现当前原生窗口、对白打开后补刷，并每 0.25 秒检查目标范围内是否缺少四项。GetTopView 的 Guide/Side 参数是忽略类型，与原生用法一致，不是参数顺序错误。启动前检查 UIMgr 是否已初始化，绑定初始化与 UI 重建增加重入保护。真正模态窗口仍阻止对白工具栏显示与按键，不为了测试绕过。

用户最新纠正：Esc 暂停菜单只提供“保存游戏/载入游戏”两项，不加快速项或任何键帽。当前只克隆原生保存与载入位图按钮、保留原尺寸和状态，总共五行沿用原生组位置；曾错误强制居中，已撤销。点击时同调用栈执行原生 CloseView(entry) 后立即发起操作；当前原生 EntryView 不是常驻窗口，CloseView 会同步移出 viewDict，不等待动画或下一帧。其关闭清理不释放新建保存菜单的服务暂停。旧 105/119 在对白及对白暂停菜单内只吞掉，独立新绑定负责分派。
