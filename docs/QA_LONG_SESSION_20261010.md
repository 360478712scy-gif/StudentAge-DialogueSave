# 0.2.13 长时间字幕卡顿修正

本轮处理用户反馈的游玩一段时间后逐字字幕卡顿、可能闪退。此前原版风格切换反馈已由用户确认属于反馈者自己的问题，本轮不再更改该功能。0.2.13 已备份后安装本机生产 DLL，随后按用户授权及追加跳过检查要求发布 Steam。

每句回跳检查点原先重新序列化、保留整份原生对白日志，累计日志产生平方级重复数据。世界快照也以完整原始字节保留。现在日志使用不可变共享前缀，只序列化新增或实际改变的行；逐句完整世界数据交由后台无损压缩，相同世界共享缓冲。完整历史、世界、随机、效果阶段和选项仍保留，没有按条数或容量删历史。第三方改变旧行时逐字段核对并建立独立分支，旧检查点保持原状；清空历史和卸载时释放捕获缓存。

历史存档仍写 HistoryTrail v2，兼容 v1；恢复、分支预检和 UI 导入时展开完整日志，已压缩块的前驱引用只保留对应紧凑世界。普通存档的世界与对白序列化格式没有改变。

## 验证结果

同一隔离 CrossOver 玩家、相同夹具直接捕获并保留 350 份完整检查点的对照：

| 指标 | 修改前 0.2.12 | 修改后 0.2.13 |
| --- | ---: | ---: |
| 托管内存增长 | 223.80 MB | 21.72 MB |
| 最后 50 次捕获中位耗时 | 2.88 ms | 2.31 ms |
| 最后 50 次捕获 P95 | 3.82 ms | 2.75 ms |
| 最后 50 次最大耗时 | 100.21 ms | 2.88 ms |

内存增长减少 90.3%。修改后继续累计至 2000 份检查点，增长 104.14 MB，末段捕获中位 2.35 ms / P95 3.03 ms，最早检查点仍完整。测试初始预热不同，因此不比较第一次 JIT 耗时。旧生产 `DialogueHistory.Tick` 已有相同世界去重，而旧直接捕获基线未执行该层去重；表格是适配器压力测试结果，不能当成所有实际剧情的固定内存或帧率降幅。

- 独立检查：存储 128、配置 26、历史 25、存档范围 81，通过。
- 隔离玩家 275 项检查通过，包含既有启动与夹具检查。专项覆盖 2000 份历史保留，第三方修改早期日志后旧快照不变，350 份完整世界和序列化呈现的压缩往返及嵌入历史加载、分支预检和全部跳转入口导入。
- 从第 1 / 1000 / 2000 份检查点恢复真实原生界面，日志长度和内容准确；原生逐字演出追加 100 个位置，全部完整记录且不产生逐句磁盘档。
- 真实效果回退：选择 A 后回到选项改选 B，仅应用 B；回到效果前逐字位置移除后续效果，继续后原效果恰好一次。对应 100 个实际位置捕获中位 2.63 ms / P95 3.18 ms，效果回退通过。
- v1/v2 旧格式、增长日志、不同长度世界、共享世界、改写早期行、截断新分支、缓存重用及前驱变化重新编码通过。
- 正式代码／存档／原生偏好共 1862 项在隔离运行与安装前后哈希核验不变。只有订阅目录的生产插件 DLL 被本机替换，QA 重写程序集没有安装。

中间失败：测试最初直接调用普通捕获时夹具尚在逐字阶段，改为捕获其完整历史状态；呈现往返比较改用实际序列化 JSON，兼容既有 float 和空字符串 JValue 的解析表示；效果测试从中途恢复后过早调用原生 RefreshTalk，两个字幕 tween 重叠导致超时，改为等待原生 AnimEnd 后切换测试节点。未通过改变生产字幕、快进或效果机制规避断言。
